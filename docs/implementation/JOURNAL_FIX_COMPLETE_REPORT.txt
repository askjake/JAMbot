Issue: Journal entries not being created despite chat summary feature working

================================================================================
                              ROOT CAUSE ANALYSIS
================================================================================

The journal writing functionality was NOT working because the code was calling
the WRONG function. There are TWO separate systems in the codebase:

1. CHAT SUMMARY SYSTEM (app/analytics/service.py)
   - Creates ChatSummary records
   - Used for analytics and conversation quality metrics
   - This was being called and working correctly

2. USER JOURNAL SYSTEM (app/journal/service.py)  
   - Creates UserJournal records
   - User-facing conversation journals with psychoanalysis
   - This was NEVER being called!

The bug was in app/message/service.py:_trigger_journal_generation()
which was importing and calling summarise_conversation_async() from analytics
instead of the journal service.

================================================================================
                              HOW IT WORKS NOW
================================================================================

TRIGGER CONDITIONS:
1. Conversation has at least 5 messages
2. User sends a message with farewell phrases:
   - "goodbye", "bye", "see you", "talk to you later"
   - "thanks for your help", "that's all", "i'm done"
   - "thank you", "ttyl", "gotta go", "have a good"

EXECUTION FLOW:
1. User sends message with farewell → message saved
2. _save_message_metadata() checks message count and content
3. _should_generate_journal() detects farewell phrase → returns True
4. _trigger_journal_generation() creates background task
5. BackgroundTaskManager executes generate_journal_background_task()
6. Journal service:
   a. Retrieves conversation from LangGraph checkpoint
   b. Formats messages for analysis
   c. Calls LLM with JOURNAL_ANALYSIS_PROMPT
   d. Parses JSON response into JournalAnalysis
   e. Stores in user_journal table as UserJournal record
7. User can view journal via /api/journal/my endpoint

================================================================================
                              DATABASE SCHEMA
================================================================================

TABLE: user_journal
- journal_id (UUID, primary key)
- owner_id (text, foreign key to user_state)
- chat_id (UUID, foreign key to chat)
- journal_type (string, default "conversation")
- summary (text, the main summary)
- psychoanalysis (jsonb, user goals, emotional tone, etc.)
- interaction_patterns (jsonb, communication style, preferences)
- user_preferences (jsonb, response format preferences)
- topics (jsonb, topics discussed)
- sentiment_analysis (jsonb, optional)
- created_at (timestamp)
- conversation_start (timestamp)
- conversation_end (timestamp)
- message_count (integer)
- status (string, default "active")
