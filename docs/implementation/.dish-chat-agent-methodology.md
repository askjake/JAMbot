# Dish-Chat Agent Work Methodology

## 🎯 PREFERRED WORKING METHOD

**When making ANY changes to the Dish-Chat codebase, ALWAYS follow this methodology:**

### 1. 🔒 Work in Sandbox ONLY
- **NO direct changes to production code**
- All development and testing in `/tmp/dish_chat_agent/` or similar
- Create complete, tested solutions before touching production

### 2. 🧪 Thorough Testing
- Test all code changes in sandbox
- Verify syntax with `python -m py_compile`
- Run basic functionality tests
- Check for import errors
- Validate logic flow

### 3. ✅ Double Check Everything
- Review all changes line by line
- Verify file paths are correct
- Check for typos and syntax errors
- Ensure backwards compatibility
- Validate database migrations

### 4. 📝 Verbose Script Annotations

**ALL scripts must be thoroughly annotated:**

```bash
✓ Header block with:
  - Script name and purpose
  - Author/date information
  - Usage examples
  - Dependencies and requirements
  - Expected inputs and outputs

✓ Section headers for major blocks:
  - Clear separators with ASCII art
  - Descriptive section names
  - Purpose of each section

✓ Inline comments for complex logic:
  - Explain WHY, not just WHAT
  - Document assumptions
  - Note any gotchas or edge cases
  - Reference related code/docs

✓ Function documentation:
  - Purpose of function
  - Parameters and types
  - Return values
  - Example usage
  - Error handling approach

✓ Variable explanations:
  - Purpose of important variables
  - Expected format/values
  - Source of data
```

### 5. 📦 Provide Comprehensive Update Script

The update script MUST include:

```bash
✓ Automatic backup of ALL modified files
  - Timestamped backup directory
  - Full file copies, not diffs
  - Located in project backups/ directory

✓ Move changed files into place
  - Copy from sandbox to production
  - Preserve permissions
  - Validate file existence

✓ Automatic testing after deployment
  - Python syntax validation
  - Import checks
  - Basic smoke tests
  - Service restart if applicable

✓ Automatic rollback on failure
  - If ANY test fails, revert ALL changes
  - Restore from backup automatically
  - Clear error messages
  - Exit with error code

✓ Manual rollback command
  - Simple one-line command to revert
  - Documented in script output
  - Standalone rollback script created
```

### 6. 📋 Documentation Requirements

Every change package must include:

- **README.md** - Complete documentation
- **CHEAT_SHEET.txt** - Quick reference guide
- **Reference implementations** - Complete code examples
- **Migration scripts** (if database changes)
- **Testing guide** - How to verify the changes work

### 7. 🎨 Output Format

Use clear, colorful terminal output:
- 🔵 Blue for INFO
- 🟢 Green for SUCCESS  
- 🟡 Yellow for WARNING
- 🔴 Red for ERROR
- ASCII box drawing for visual hierarchy

### 8. 📁 Standard Locations

- Sandbox work: `/tmp/dish_chat_agent/<session_id>/`
- Backup directory: `~/dish-chat/backups/fix_YYYYMMDD_HHMMSS/`
- Fix packages: `/tmp/dish-chat-fixes/`
- Project root: `~/dish-chat/`

1. **Safety** - No accidental production changes
2. **Reliability** - Tested before deployment
3. **Reversible** - Easy rollback if issues
4. **Documented** - Clear understanding of changes
5. **Professional** - Production-ready approach
6. **Confidence** - User can trust the changes
7. **Maintainable** - Verbose annotations
8. **Debuggable** - Clear comments
