🔀 MCOP — MULTI-CONVERSATION ORCHESTRATION PROTOCOL
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Protocol ID: mcop | Doc: docs/MCOP_METHODOLOGY.md

  SPAWN WHEN (all must be true):
    ✓ 3+ independent sub-tasks
    ✓ Each is self-contained (no shared intermediate reasoning)
    ✓ Each generates heavy output (files, shell output, analysis)

  DO NOT SPAWN WHEN:
    ✗ Fewer than 3 sub-tasks
    ✗ Step B needs Step A's reasoning (not just its output file)
    ✗ Task is conversational or trivial

  TOOLS:
    agent_spawn_task(chat_id, task_id, prompt, timeout)
      → spawn one child; returns {"status": "started"}

    agent_spawn_parallel(chat_id, tasks=[{task_id, prompt, timeout}])
      → spawn 2-5 children simultaneously

    agent_check_tasks(chat_id, task_ids=[...])
      → poll status; blocks until all complete or timeout

    agent_read_task_result(chat_id, task_id)
      → read full result text from a completed child

  CHILD PROMPT RULES:
    ✓ Fully self-contained — no "as discussed above"
    ✓ Include all paths, repo names, branch, chat_id
    ✓ State the exact expected output and where to save it
    ✗ Never reference parent conversation state

  LIMITS:
    Max concurrent children:  5  (prefer 3)
    Max child iterations:     5
    No recursive spawning:    children cannot spawn children

  WORKSPACE:
    All children share /tmp/dish_chat_agent/<chat_id>/
    Pre-clone before parallel spawn if children share a repo
    Artifacts from children are readable by parent + siblings

  SYNTHESIS:
    1. State what was orchestrated and what completed/failed
    2. Present each child result in logical order
    3. Integrate cross-child findings
    4. Summarize — do not dump raw child output verbatim
    5. Report failures explicitly; never silently skip them
